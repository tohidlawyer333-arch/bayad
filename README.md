# باید | Bāyad

**باید** یک نمونه‌ی اولیه‌ی اندرویدی بومی برای تبدیل هدف‌های شخصی به قدم‌های کوچک و قابل انجام است. رابط کاربری فارسی و راست‌به‌چپ است؛ هیچ حساب کاربری، سرور، API یا کلید محرمانه‌ای لازم ندارد.

## امکانات

- ساخت مسیر از هدف آزاد؛ قدم‌های گام‌به‌گام با بازشدن قدم بعدی پس از تکمیل پیش‌نیاز.
- اگر قدم قبلی را از حالت انجام‌شده خارج کنید، وضعیت انجام‌شده‌ی قدم‌های بعدی حفظ می‌شود؛ اما تا رفع وابستگی قفل و با برچسب «نیاز به مرور» نمایش داده می‌شوند.
- مکث و ادامه، نمایش پیشرفت، تعامل «کمک می‌خوام» و امکان ساخت مسیر تازه/تغییر هدف.
- ذخیره‌ی هدف، قدم‌ها، وضعیت انجام، مکث و تم در `SharedPreferences` خصوصی برنامه با JSON.
- پنج تم: سرمه‌ای، آبی، سبز کله‌غازی، صورتی و گلبهی. رنگ اصلی در سربرگ‌ها و نواحی شاخص استفاده شده و سطح کار سفید/روشن برای خوانایی و تمرکز نگه داشته شده است.
- قالب‌های محلی نمونه برای آب‌رسانی، مطالعه و هدف مالی؛ در غیر این صورت مسیر عمومی و عملی پیشنهاد می‌شود.
- صفحه‌ی خوش‌آمد و نمونه برای شروع سریع؛ فونت از فونت سیستمی دستگاه است.

## مغز برنامه: منطق است، نه هوش مصنوعی

نسخه‌ی MVP **هوش مصنوعی ندارد**. `LocalPlanner` یک موتور قطعی و روی دستگاه است: چند کلیدواژه را برای تشخیص الگوها بررسی می‌کند و برایشان الگوهای ثابت تولید می‌کند؛ اگر الگویی پیدا نشود، مسیر عمومی می‌سازد. این روش ساده، قابل بازبینی، آفلاین و بدون ادعای «فکرکردن» یا درک معنایی است. تشخیص کلیدواژه کامل نیست و این برنامه مشاور حقوقی یا جایگزین کمک تخصصی نیست.

### ایمنی و مسیر پیامد

برای تعدادی از کلیدواژه‌های مرتبط با سرقت، کلاهبرداری/جعل، خشونت و آسیب‌رسانی، برنامه به‌جای دستورالعمل عملیاتی مسیر پیامد نشان می‌دهد: روشن‌کردن نیاز پشت خواسته، بررسی منصفانه‌ی پیامدهای *ممکن*، سنجش هزینه‌ها، یافتن حداقل سه دسته راهکار قانونی و انتخاب اقدام امن بعدی. متن عامدانه نمی‌گوید زندان یا پیامد مشخصی قطعی است: نتیجه‌ی حقوقی به جزئیات و قانون محل است و برنامه قطعیت حقوقی ادعا نمی‌کند. رویکرد غیرقضاوتی است؛ در خطر فوری، کاربر را به خدمات اضطراری محل ارجاع می‌دهد. فهرست واژگان یک محافظ محدود و غیرکامل است، نه سامانه‌ی تشخیص خطر.

### معماری امنِ آینده (پیاده‌سازی نشده)

اگر در آینده برنامه‌ریز هوشمند اختیاری اضافه شود، پیشنهاد می‌شود درخواست از یک backend تحت کنترل سرویس عبور کند، لایه‌ی سیاست/ایمنی پیش و پس از مدل اعمال شود، خروجی به JSON ساخت‌یافته با طرح‌واره‌ی محدود تبدیل و اعتبارسنجی شود و یک gatekeeper محلی آن را دوباره بررسی کند. باید مسیر آفلاین و مسیر ایمنِ جایگزین حفظ شوند. **هیچ کلید API یا راز سرویس نباید داخل APK قرار بگیرد.** این پیشنهاد صرفاً توضیح معماری است؛ کد فعلی هیچ اتصال هوش مصنوعی یا شبکه‌ای ندارد.

## حریم خصوصی

داده‌ی مسیر در `SharedPreferences` خصوصی همین نصب ذخیره می‌شود و برنامه در کد فعلی هیچ داده‌ای را ارسال یا با سرویس بیرونی همگام نمی‌کند. مجوز اینترنت، دسترسی‌های دیگر و تحلیل‌گر/analytics تعریف نشده‌اند. حذف داده‌ی برنامه از تنظیمات Android، داده‌ی محلی را پاک می‌کند. از متن هدف در بکاپ سیستمی دستگاه نیز ممکن است طبق تنظیمات سیستم نسخه‌ی پشتیبان تهیه شود؛ برای داده‌ی بسیار حساس از این نمونه‌ی اولیه استفاده نکنید.

## باز کردن و بیلد در Android Studio

1. Android Studio به‌روز نصب کنید و SDK Platform 35 و JDK 17 را از SDK Manager در دسترس قرار دهید.
2. ZIP را استخراج کنید و فولدر `Bayad` (ریشه‌ای که `settings.gradle.kts` دارد) را با **File → Open** باز کنید.
3. اجازه دهید Android Studio Gradle 8.7 و افزونه‌های Gradle/Kotlin را از مخازن پیکربندی‌شده دریافت کند؛ برای دریافت وابستگی‌ها، اتصال شبکه هنگام بیلد لازم است.
4. با **Build → Make Project** یا `./gradlew assembleDebug` بسازید. شناسه‌ی برنامه `ir.bayad.app` است.

تنظیمات حاضر: AGP 8.5.2، Kotlin 2.0.20، Gradle 8.7، Compose Material 3، compile/target SDK 35، min SDK 26 و Java 17. در این محیط تولید، Java، Gradle و Android SDK نصب نبودند؛ بنابراین اجرای واقعی `assembleDebug` و آزمون روی دستگاه ممکن نشد.

### نکته‌ی Gradle Wrapper

فایل‌های `gradlew`، `gradlew.bat` و `gradle/wrapper/gradle-wrapper.properties` در پروژه هستند، اما `gradle-wrapper.jar` در محیط ساخت موجود نبود و شبکه نیز در دسترس نبود؛ بنابراین JAR ساختگی یا خراب اضافه نشده است. برای اجرای واقعی wrapper، روی سیستمی که Gradle دارد از ریشه اجرا کنید: `gradle wrapper --gradle-version 8.7`؛ یا پروژه را با Android Studio باز کنید تا Gradle را provision کند. فایل `gradle/wrapper/gradle-wrapper.jar.note.txt` این محدودیت را ثبت می‌کند.

## انتشار در GitHub

از ترمینال در ریشه‌ی پروژه (پس از ساخت/بررسی wrapper) می‌توانید اجرا کنید:

```bash
git init
git add .
git commit -m "ساخت نسخه اولیه برنامه باید"
git branch -M main
git remote add origin https://github.com/USERNAME/bayad.git
git push -u origin main
```

پوشه‌های خروجی مانند `build/` و فایل‌های محلی Android Studio طبق `.gitignore` وارد Git نمی‌شوند.
